# Day2｜学员真实需求 Lab Runbook

三个任务都从 `RAW_REQUEST.md` 开始。控制节奏的对象是“需求如何变成可验收任务”，不是平台操作技巧。

## 01｜Amazon Competitor Discovery

【原始需求】

“在 Amazon 搜索一个关键词，按畅销情况找到 Top10 产品，把主要产品信息提取出来。”

【现场先问什么】

站点、关键词、Top10 口径、Sponsored 处理、字段、重复 / 变体规则、缺失值规则、采集截止时间。先在白板上分开写：搜索位置、Sponsored、Organic、BSR。BSR 必须连同具体类目记录；不同类目的 BSR 不得直接横向比较或合并排序；BSR 也不得解释为销量件数。

【最终任务定义】

用现场答案补全：在 `[站点]`，以 `[关键词]` 获取 `[时间]` 的公开搜索截面；按 `[Top10 口径]`、`[Sponsored 规则]` 和 `[去重规则]` 整理 10 条，输出 `[字段]` 与来源；缺失值按 `[规则]` 处理。不要把搜索顺序解释为销量排名。

【推荐时长】

第一次执行与验收 45–55 分钟；Skill Lab 与第二关键词复跑 30–40 分钟。

【执行路径】

打开 `workspaces/codex/day2-live-tasks/01-amazon-competitor-discovery/` → 读原始需求 → 澄清 → 复述任务定义 → Live 搜索 → 识别广告与候选 → 去重 → 必要时查看详情 → 生成 Excel / notes → 验收。

【看什么】

Agent 是否主动暴露“畅销”的歧义；Sponsored 与 Organic 是否分开；是否有 10 条“按确认口径”的结果；ASIN 去重、变体处理、来源、采集时间和缺失字段是否一致。

【容易翻车的位置】

把搜索前 10 写成销量前 10；为了填 BSR 乱猜；跨类目比较 BSR；重复 ASIN 占多个位置；广告标记丢失；列表页和详情页时间截面混淆；把不可见字段从第三方摘要补成事实。

【Live 失败时如何切 Offline】

第一次任务说清失败类型与切换时间，不改变任务口径，只把来源切到 `input/offline/`。先打开教学搜索页，再按需要打开详情页；即使现场排除 Sponsored，去重 Organic 仍能形成 Top10。结果必须标注 `FICTIONAL / TEACHING SNAPSHOT`，不能作当前市场结论。

【一句收口】

搜索页给的是证据片段，Top10 是先定义口径、再处理证据得到的业务结果。

【如何进入下一段课程】

让全班指出哪些步骤依赖本次关键词、哪些步骤每次都应该相同；把后者带入 Skill Lab。

【如何进入 Skill Lab】

先验收第一次输出，再要求现场从成功执行中抽取 Trigger、Inputs、Scope、Discovery、广告处理、去重、证据、缺失数据、输出契约、人工复核和自检。学员自己把 Skill 创建到 `.agents/skills/amazon-competitor-discovery/SKILL.md`；创建前该路径必须不存在，创建后必须显式检查路径正确。不要展示讲师 Plan B，除非现场卡住。

【第二关键词怎么选】

从 `electric milk frother`、`portable blender`、`travel coffee mug` 中让现场选一个进行 Live；不要使用第一次关键词，不要沿用第一次会话，也不要粘贴第一次答案，只提供新关键词 / 新业务输入。选择应独立于第一次商品集合，又能观察广告、去重与字段一致性。

若第二次 Live 失败，明确告诉学员：“为了保留‘换任务复用 Skill’这个实验，只把数据源切换成 electric milk frother 教学快照。”然后使用 `input/offline-second-run/` 继续复用实验。该目录只替换数据源，不替换 Skill，也不能把第二次商品结果写入 Skill。

【Skill 验收重点】

Skill 是否确实位于 `.agents/skills/amazon-competitor-discovery/SKILL.md` 并被新会话发现；是否仍遵守现场确认的 Top10 定义；Sponsored、去重、字段、缺失值和来源规则是否稳定；是否擅自扩大搜索范围；是否混入第一次或第二次商品 ID、品牌、价格或答案；BSR 是否带类目且未跨类目排序。失败时先修 Skill，再新开会话复验。

## 02｜Instagram Lead Discovery

【原始需求】

“在 Instagram 搜索 wig salon 类的账号。”

【现场先问什么】

国家 / 城市、目标类型、市场观察还是潜客开发、数量、排除项、什么算有效 Lead、哪些情况必须人工复核。现场无人给地域时，可提议 Los Angeles，但需确认。

【最终任务定义】

用现场答案补全：在 `[地域]` 发现 `[目标类型]` 公开商业账号，用于 `[用途]`；先形成候选，再按 `[纳入 / 排除规则]` 筛选 `[数量]` 个可复核 Lead；输出公开字段、来源、匹配理由、风险、置信度和人工复核项。

【推荐时长】

35–45 分钟。

【执行路径】

打开 `workspaces/codex/day2-live-tasks/02-instagram-lead-discovery/` → Plan First → 确认范围 → Live 公开搜索 → 候选池 → 查看公开 Profile → 分类与筛选 → Lead List → 人工复核。

【看什么】

搜索结果是否只被当作候选；地点、账号类型和活跃信号能否追溯；拒绝项有没有理由；不确定项是否诚实进入 Manual Review；最终名单是否满足现场用途。

【容易翻车的位置】

从区号、照片或风格猜城市；把品牌 / 电商自动当 salon；把粉丝数当采购意向；看到名字相关就纳入；漏掉 source；擅自开始关注、私信或批量营销。

【Live 失败时如何切 Offline】

记录登录 / 页面 / 访问限制后，切到 `input/offline/search-results.html` 与 `profiles/`。继续执行同一筛选规则；提醒所有账号与联系方式均为虚构教学数据。

【一句收口】

搜索不是结果，筛选之后形成业务对象才是结果。

【如何进入下一段课程】

对比 Amazon：两者都要定义范围和证据，但 Instagram 的核心产物是“符合用途且可人工复核的对象”，不是排名表。

## 03｜Data Analysis → Dashboard

【原始需求】

“给你一份业务数据，帮我分析统计一下，再用图表 / Dashboard 展示。”

【现场先问什么】

受众与决策、时间 / 市场 / 渠道范围、核心问题、指标口径、数据质量处理、异常是否保留、总览还是诊断。让 Agent 先读工作簿 README 与数据字典。

【最终任务定义】

用现场答案补全：针对 `[受众 / 决策]`，分析 `[范围]`，重点回答 `[业务问题]`；按 `[指标与质量口径]` 形成可追溯分析、输出工作簿与可离线打开的单文件 Dashboard；异常和不能得出的结论必须披露。

【推荐时长】

50–65 分钟。

【执行路径】

打开 `workspaces/codex/day2-live-tasks/03-data-analysis-dashboard/` → 读数据字典 → 数据体检 → 确认口径 → 分析 / 统计 → 异常与解释边界 → 选择图表 → 生成三项输出 → 断网打开 Dashboard → 指标抽查。

【看什么】

是否发现重复、空值和高值；指标分母与去重规则；图表标题是不是业务问题；图、表、结论是否同口径；同步变化是否被错误写成因果；关键数字能否回到汇总表。

【容易翻车的位置】

覆盖原始工作簿；直接求和库存；平均百分比；忽略重复；静默删除异常；跨市场金额口径不说明；使用 CDN 造成断网空白；为了四张图堆无意义图。

【Live 失败时如何切 Offline】

此任务默认就是离线本地数据。若图表库或浏览器预览失败，要求改成单文件内嵌 CSS / SVG / Canvas；讲师仅在时间不足时打开 `instructor/day2-data-dashboard-reference.html` 解释验收口径，不把它复制到学员 workspace。

【一句收口】

AI 做图并不难，难的是它知不知道这张图想回答什么问题。

【如何进入下一段课程】

用“可追溯指标 + 暴露限制 + 人工验证”回扣三个任务的共同验收逻辑，再进入后续课程。
