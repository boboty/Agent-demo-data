# V1 数据集设计

## 设计目标

数据规模以课堂可读性为先：人可以肉眼抽查，AI 又有足够记录形成主题、比较方案并暴露错误判断。所有数据均为固定规则生成的虚构数据，不包含真实客户或个人信息。

## 关联模型

`products.xlsx` 是 SKU 主数据入口。规范化后的 SKU 连接 `search_terms.xlsx`、`orders.xlsx`、`inventory.xlsx` 和 `cost_parameters.xlsx`；`supplier` 连接产品采购成本与 `supplier_quotes.xlsx`。Listing、评论和客服通过手摇 G2 的产品事实、颜色 / 套装、使用场景和问题主题建立语义关联。

广告销售额是 Amazon Ads 聚合归因口径，广告表中的 `sku` 表示被投放 SKU，不保证等于最终购买商品；相关商品购买可能使单均归因销售额不同于该 SKU 的标准价。

`orders.xlsx` 是为了订单异常课堂任务抽取的**非代表性订单样本**，保留不同状态、履约方式和异常记录，不是 7 月店铺全量订单。`inventory.xlsx` 的 `avg_daily_sales` 是独立的运营补货口径，代表更完整的历史销量基线。因此订单样本行数、广告归因订单和库存日销不得直接对账，也不得反推采样率。三者可做 SKU、价格、时间范围和趋势层面的检查，但不声称逐单或总量一一对应。

## 数据文件与场景

| 文件 | 课堂用途 | 主要关系 |
|---|---|---|
| `products.xlsx` | SKU 清洗、产品资料整理 | SKU 主数据，连接供应商 |
| `listing_current.md` | Listing 事实核验与优化 | 基于 G2 事实并保留表达风险 |
| `search_terms.xlsx` | Search Term 清洗与广告判断 | 引用在售 SKU，包含不同样本量和表现类型 |
| `supplier_quotes.xlsx` | 报价标准化与综合比较 | 供应商、币种、MOQ、交期等多维权衡 |
| `reviews.csv` | 主题聚类、评论归因 | 与产品体验、Listing 预期偏差相关 |
| `customer_service.csv` | 分类、升级和回复草拟 | 与评论主题及高风险场景相关 |
| `orders.xlsx` | 订单异常、退款、延迟分析 | 非代表性异常分析样本；引用 SKU 和售价，保留少量缺失与状态差异 |
| `inventory.xlsx` | 断货、滞销、信息不足判断 | 引用 SKU，结合日销、交期、安全库存 |
| `cost_parameters.xlsx` | 后续利润测算输入 | 引用 SKU、售价和采购成本 |

## 原始、工作与基线

- `data/raw/`：只读初始数据。
- `data/work/`：课堂操作副本，允许清洗和改写。
- `data/expected/`：课堂工作副本的恢复基线。
- `outputs/`：结果文件，与输入数据分离。

## 有意不做的精确关系

评论与客服不绑定真实个人或订单；广告归因订单不反向伪造到订单表；供应商报价不强造唯一最佳答案。这些边界用来训练学员区分“可关联分析”和“无法证实的精确因果”。
