# BrewGo G2 Listing 优化任务卡

## 1. 目标

基于当前工作区中的事实资料，优化 BrewGo G2 当前 Amazon Listing，使建议稿更准确、清楚，并减少未经证实、绝对化或可能引起错误预期的表达。

## 2. 输入资料

- input/listing_current.md：待核对和优化的当前 Listing 草稿，不是产品事实来源。
- input/product_profile_g2.md：已确认的 G2 产品事实。
- input/products.xlsx：产品、SKU、变体、颜色和价格等资料。
- input/reviews.csv：客户体验与预期偏差线索；评论不能单独证明产品缺陷或原因。

如果当前工作区另有 project-context.md 和 business/，应将其作为长期项目规则和辅助事实来源；如果没有，不自行假设。除此之外，资料没有提供的产品能力、规格、兼容性、配件或市场结论均视为未知。

## 3. 约束

- 不补造产品能力或数据；推测必须明确标记。
- 当前 Listing 中的具体说法必须与输入资料核对，不能因其已经写在草稿中就当作事实。
- 区分已确认事实、评论线索和待确认信息。
- 不把单条或一组评论直接写成确定的产品缺陷归因。
- 高风险或无法确认的内容列入人工确认项。
- 只输出建议，不直接发布或修改线上 Listing。

## 4. 输出

在 outputs/ 中保存：

1. listing-recommendation.md：新的标题、五点、描述和后台搜索词建议稿。
2. issue-list.md：当前草稿的问题清单，标明问题、依据、建议处理方式和证据状态。
3. manual-review.md：高风险、资料缺失或无法确认的事项。

重要修改应尽量注明依据文件；如果保留某个有争议的说法，也要解释依据。

## 5. 验收

- 建议稿覆盖标题、五点、描述和后台搜索词。
- 关键产品说法可追溯到输入资料。
- 未确认信息没有被包装成事实。
- 当前 Listing 的明显事实冲突和绝对化表达得到处理。
- 问题清单与建议稿一致，没有只改文案而遗漏风险说明。
- 人工确认项单独列出，且没有发生发布、改价或其他外部动作。
